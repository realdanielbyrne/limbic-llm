# Round-11 code review before GPU time (4 Nov 2026)

**What was reviewed:** the round-11 changes to `experiments/evolve/w1s_slots.py`, `eval_by_query.py`, `run.py`, plus the new files `names.py`, `fit_code.py`, `toy_keep.py`, `toy_time.py` and their tests. The spec is the runbook `research/plans/round11_runbook.md` §3–§4.

**How:**
- Three adversarial reviewers, each with its own lens:
  1. E1/E2 (causality and the streaming reference);
  2. hooks, controls and the evaluation path;
  3. task generators and the gate scripts.
- Two independent refuters checked each finding.
- Result: 16 findings; 14 survived at least one refuter.
- Each fix has a regression test (`tests/test_evolve_w1s.py`, `tests/test_evolve_eval.py`, `tests/test_toy_time.py`).

**E1/E2: no leaks found.** The E1/E2 reviewer tried every new option on top of the I1 recipe:
- larger T and more evictions;
- odd K/M/P;
- the hyst, schmitt and dense gates;
- float32 and bf16-rounded input.

It found no read of a future position and no divergence between the parallel and streaming forms.

## Findings and resolutions

| ID | Lens | Severity | Finding | Resolution |
|---|---|---|---|---|
| F0 | E1/E2 | minor | The superposed store accepted `--w1s-time-feat` and non-linear `--w1s-recency-form`. They did nothing, but added parameters | Refused (`SlotLoop._round11`) |
| F1 | E1/E2 | minor | A `w1s_time_feat` override keeps the linear penalty | Refuted by both verifiers (documented merge order); handled with F5 anyway |
| F2 | E1/E2 | minor | The learned keep scorer scores the successor x_{j+1}; the execution plan said h_j | Kept as is, deliberately: like the value-norm mode, it scores the token whose value is stored. The help text now says so. Recorded in the NOTEBOOK |
| F3 | hooks | major | `--w1s-keep-by` without `--w1s-keep M` silently kept every entry, while the output was labelled as a keep variant. G0.4's ceiling against value-norm comparison would have passed trivially | Refused (`--w1s-keep-by X needs --w1s-keep M > 0`) |
| F4 | hooks | major | `--w1s-set` on a flag that only sets an initial value (sup_*, recency, align/lex init, density, …) was overwritten by the checkpoint, so the result was the trained model under an override's name | Refused, pointing to `--w1s-param` (eval_by_query.py compares fresh builds under the same seed) |
| F5 | hooks | minor | An eval-time `w1s_time_feat` override keeps the run's recency form, whereas training resolves it to `none` | Now requires an explicit `--w1s-set w1s_recency_form=…` |
| F6 | hooks | minor | Different evaluations could share a default output path, and the seed was not recorded | `out["eval"]` records seed, n, batch and the attention layers; a non-default seed adds a `.seed<N>` suffix. Stage-0 jobs always pass `--out` |
| F7 | hooks | minor | supw fire diagnostics gave a slot to a fact by its onset, not by the tokens its key pools from | Owner = the fact covering at least half of the key window [s − P, s − P + pool − 1] |
| F8 | tasks | major | Name rule beyond 20 statements: the queried fact was the only training-list name in about 80% of sequences. That was a shortcut in the decoys-20, 4096×24 and 8192×32 cells | Every list name now appears in every such sequence; the queried name is one of them |
| F9 | tasks | major | G0.8's gate, read literally at the training length, does not discriminate: every arm "learns", the concatenated-time reference passes, and rope passes while it loses content selection at 2× and 4× | The gate reports the **literal** reading and a **strict** one (drop rule at every length; order must beat both linear and `none`), plus a calibration block. Which reading decides is Daniel's call; a rule change is a DEC |
| F10 | tasks | minor | G0.8's `concat` arm is not the merit arm that failed 0/10. That arm multiplied a time-since-onset code into a superposed store's key, from an unfinished run | Documented in `toy_time.py`. The runbook's G0.8 wording ("additive/concatenated key code") is what the arm implements. Results must not claim rope/ordinal "avoid the merit failure" |
| F11 | tasks | minor | The syllable pool was disjoint from the name lists as strings, not as tokens: "Tomi" shares the token ' Tom' | Names that start with a reserved name are dropped (no runs had used the pool yet) |
| F12 | tasks | minor | Pool-trained runs are evaluated on the training names | Refuted by both verifiers (the intended like-for-like comparison) |
| F13 | tasks | minor | `fit_code.make_task` ignored the run's name pool and tail | Mirrors run.py: pool, tail and mix |
| F14 | tasks | minor | `--w1s-set w1s_code=learned` without a fitted W_z silently evaluated a random code | Refused, unless `--allow-random-code` (recorded in the output) |
| F15 | tasks | minor | update-k: digit 1 differed only from the previous code, not from all earlier ones | It now differs from all earlier codes, and k ≤ 9; k = 1 sequences are unchanged |
