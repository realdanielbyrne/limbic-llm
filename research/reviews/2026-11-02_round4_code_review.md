# Review RV3: round-4 code review (W1i, scattered needle task, goal diagnostic), 2 Nov 2026

Two independent reviewers (W1i; task and diagnostic) read `experiments/evolve/w1i_events.py`, `tests/test_evolve_w1i.py`, `ScatterNeedleTask` in `experiments/evolve/run.py` and `experiments/evolve/diag_goal.py` at commit `f64e84d`, while the round-4 GPU runs were in flight. Each finding was then checked by an adversarial verifier on CPU. **No leak was found.** Every finding below was confirmed (holds = true) and is fixed or addressed. Cite as `RV3.<id>`.

| ID | Severity | Location | Finding | Status |
|---|---|---|---|---|
| w1i-1 | medium | `tests/test_evolve_w1i.py:55-77` | The mechanism test does not exercise EventLoop._read or event_strength. Only goal_context comes from the module. The hindsight key shift, the values, alpha = 1, the event gate and the scan (gated_delta_scan, not the chunked _run that _read uses) are all re-implemented in the test. No other test checks how _read wires the G path, so the suite cannot catch a wiring bug in the code the GPU actually runs. | Fixed in `672406d`: `test_read_wires_the_goal_field_as_described` spies on the module's `_run` calls |
| w1i-2 | low | `experiments/evolve/w1i_events.py:102` | StartLoop.__init__ creates g_beta, and EventLoop computes it in _gates and then throws it away (`ga, _ = ...`). Its weight and bias never get a gradient. They are still counted as trainable parameters (n_train at pretrained_loop.py:717 and the E3 budget test), and every forward pays for the projection. | Fixed in `672406d`: `g_beta` deleted; G's decay computed directly |
| w1i-3 | low | `experiments/evolve/w1i_events.py:17` | The docstring says the event detector 'starts sparse' (b_e = -2), but sigma(-2) is about 0.12 at every token. At initialisation G is therefore written densely, with no decay. G is also read after the write at the same position, and consecutive drifting contexts are highly correlated (c_t . c_{t-1} is about rho). So G's read at t is largely an echo of the current token's own value and the one before it. The G path starts as a recency channel, not a goal field. | Fixed in `672406d` (docstring); learned sparsity is now measured by `eval_by_query.py` (round 4: mean ε 0.04, 0.23 at first digits) |
| w1i-4 | low | `tests/test_evolve_w1i.py:23-31` | The causality test's bf16 case does `torch.randn(...).to(dtype).float()`, so it only feeds float32 values that have been rounded to bf16. It never feeds a bf16 tensor, despite the docstring saying 'also for bf16 input'. A real bf16 tensor makes the module raise an error. | Fixed in `672406d` (docstring: bf16-rounded float32 input) |
| F1 | medium | `experiments/evolve/run.py:56-60` | ScatterNeedleTask keeps the facts in their original order, so their rank is unchanged and still tells you how far each fact is from the query. The docstring says the opposite: "the queried fact's position carries no information about which one it is". A memory that keeps only the first and the most recent write, the policy P18 describes, still covers every query when there are 2 pairs. With 3 pairs it would still get about 2/3 right, and run.py never breaks accuracy down by which fact was queried. | Fixed in `672406d` (docstring: rank is kept); per-rank accuracy via `eval_by_query.py`; use 3+ pairs |
| F2 | medium | `experiments/evolve/run.py:79-86` | Scattering lets a fact straddle a boundary between 64-token window blocks. The fixed layout never does this: every fact sits inside block 0. In about 4% of sequences the queried fact's name and its first digit land in different blocks. The frozen hidden state at that fact's space token and digit positions then contains no trace of the name. Any candidate that builds its key from h at those positions (W1g's DG key b at the space token, S's address) cannot bind that fact to its name. The result is a hidden cap on accuracy that the fixed-layout runs did not have. | Fixed in `672406d`: `ScatterNeedleTask(block=W)` resamples straddling facts. Round-4 scattered runs predate the fix (≈4% of facts straddled a block) |
| F3 | low | `experiments/evolve/diag_goal.py:62-69` | diag_goal's key and read metrics give the same answer for both checkpoints, so they cannot explain the first/last behaviour. On P=3 data, G's and S's reads are closest to the first fact's digit-1 value in nearly every sequence for both checkpoints. The 2-pair checkpoint does show a first/last pattern in accuracy (1.00/0.08/0.92); the 3-pair checkpoint does not (0.49/0.35/0.48). As a result query_key_closest_to_queried_fact and read_closest_to_queried_digit1 just equal the fraction of sequences where fact 0 was queried (0.520 and 0.328). s_read_fact_index_hist says S returns the first fact (250 of 256, last 0 of 256), which contradicts P18's 'the last fact comes through the delta-rule overwrite'. Only digit1_acc_by_queried_fact supports 'retrieves the first and last facts only'. The S-holds-last mechanism is not shown by what diag measures. | Addressed in the register: P18 rests on behavioural accuracy by queried fact only |
| F4 | low | `experiments/evolve/run.py:81` | ScatterNeedleTask ignores self.corpus and always draws filler from self.pool. When --text-file is given, NeedleTask sets pool=None, so every call to sample() crashes. | Fixed in `672406d`: corpus filler supported |

**Effect on results.**
- No finding affects the content-selection results P21 and P22. With 3 pairs, a first-plus-last memory cannot retrieve the middle fact, and W1i does (0.99 by rank).
- F1 means any *2-pair* scattered result still needs per-rank reading.
- F2 means P21 seed 0 (round 4) and the round-5 seed reruns ran on slightly different task versions: the round-4 runs predate the block fix.
